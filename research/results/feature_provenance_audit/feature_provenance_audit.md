# Feature provenance and V2 training-data audit

**Audit date:** 2026-10-21  
**Disposition:** **UNRESOLVED** for exact feature-generation provenance and historical V2 sample membership. The model artifact and the training algorithm are identified, but neither the four fields' complete generation semantics nor the historical run's exact input/split membership is established.

## Executive summary

The original V2 training script and its configured input are present in the protected original project and were inspected read-only. The script describes an 82-column, numeric-preprocessing pipeline: a seeded per-class reservoir sample capped at 100,000 rows per class, followed by a stratified 80/20 split and a median-imputer/Random Forest pipeline. Its configured input is `ml/processed_without_udplag.csv`, currently present in the original folder at 22,316,232,040 bytes. The script does not save sampled row identifiers or split indices, and no training-time input checksum or runtime manifest tying that CSV to the saved V2 model was found in the existing audit records.

The four disputed fields are present in the serialized schema at positions 52, 58, 81 and 82. Existing inspections establish some value and coercion behavior, but not generation semantics for any of them. `SimillarHTTP` and `Inbound` remain unresolved; the observed binary values for `CWE Flag Count` and duplicate-looking values for `Fwd Header Length.1` are not proof of their intended universal meanings.

The original preprocessing script excludes the file named `UDPLag.csv`, which supports file-level separation if that script produced the configured V2 input. It does not rule out repeated flows/tuples across the other source CSVs, and no V2 sample membership record exists to compare. Existing UDPLag evaluations and the CIC-IDS2017 benchmark do not resolve this: the former has already been used; the latter fits new research models on 78 features and is explicitly not a V2 evaluation.

## Training data, split, and overlap findings

### Confirmed from the source code

1. V2's configured data file is `ml/processed_without_udplag.csv` (`train_model_v2.py:28`), read in 50,000-row chunks (`:61–65`).
2. It drops rows with null labels, maps stripped/uppercased `BENIGN` to 0 and every other non-null label to 1 (`:71–81`), and excludes `Label`, `Flow ID`, source/destination IP, timestamp, and `Unnamed: 0` from feature columns (`:36–43`). The first chunk's remaining order becomes the feature order; later chunks are reindexed (`:84–106`). Numeric conversion and infinity handling occur before sampling (`:72`, `:106–108`).
3. It keeps up to 100,000 rows per class using `default_rng(42)` and row-wise reservoir updates (`:32–34`, `:53–57`, `:110–122`). All-missing sampled columns are removed (`:156–159`), then an 80/20 stratified random split with `random_state=42` is made (`:175–181`). The training pipeline is median imputation plus a balanced 100-tree Random Forest (`:199–215`).
4. It writes the fitted model and feature list to configured artifact paths (`:258–264`). The script has no code persisting selected source row numbers, reservoir membership, split indices, or a run manifest.
5. The preprocessing source excludes `UDPLag.csv` by filename (`preprocess.py:11–14`). This establishes intended file-level exclusion in that script. The current merged CSV's exact relation to the historical model save is not anchored by a training-time checksum or run record.

### Evidence limits and separation status

- The original merged input and ten non-UDPLag CSVs currently exist, but no training-time SHA-256 for the merged input/source files was recorded in the available V2 evidence. Current file presence and size do not prove bytes/order/runtime at model-fit time.
- V2's internal 80/20 split is algorithmically specified, but no retained split members or training-time predictions were found in the V2 artifact. There is no separate validation split in the recovered script.
- Because the V2 script discards identifiers before sampling, its artifact and current schema cannot identify the selected source rows. The separate `training_sample.pkl` / `training_sampling_state.pkl` artifacts belong to the later 10,000-per-class research protocol and do not fill this gap.
- **UDPLag file-level separation:** supported by the explicit exclusion in `preprocess.py`, conditional on that script having generated the precise historical `processed_without_udplag.csv`. **Flow/session-level separation:** unproven; duplicates across the ten included CSVs and the excluded UDPLag capture were not ruled out for the historical V2 sample.
- **Historical membership:** unproven. Replaying the saved algorithm against the current merged file could create a deterministic *reconstruction* if the runtime and source order are pinned, but without a training-time input hash, runtime record, or saved membership list it cannot certify historical membership.
- Existing same-source UDPLag evaluation results are already used and cannot be relabeled independent. The CIC-IDS2017 benchmark is a valid separate research experiment in its own scope, but it uses 78 common-named columns and refits new models; it does not evaluate frozen V2 or repair its missing four inputs.

## Prioritized resolution plan

1. **Obtain the original feature-generation bundle** used for the ten CIC-DDoS2019 CSVs: exact CICFlowMeter/custom extractor source revision or JAR/build hash, command-line options/configuration, and any post-export scripts that add/rename columns. It must include executable definitions or documented fixtures for `SimillarHTTP`, `Inbound`, `CWE Flag Count`, and `Fwd Header Length.1`. The source CSV generator plus its build/config provenance is the highest-value next artifact; a generic current upstream version is insufficient.
2. **Obtain the V2 training-run provenance record**, ideally the original run manifest containing the exact input CSV SHA-256, ordered source-file hashes/order, Python/NumPy/scikit-learn versions, and selected row/source identifiers plus train/test split indices. If no such record exists, preserve that absence; an exact replay against the current 22-GB file can only be reported as a reconstruction, never historical proof. Git history may help locate the generator or historical manifest, but the original `.git` is currently inaccessible (`git` reports permission denied), and the working copy has no Git metadata.
3. **Only after items 1 and 2:** obtain an independently sourced labeled candidate with raw captures or a documented compatible feature export; verify all 82 fields' order, units, generation, preprocessing, labels, and overlap against the recovered training IDs/flows. Evaluate the frozen model only if all checks pass. CIC-IDS2017's current 78-feature research benchmark remains a separately refitted comparator, not a substitute for this requirement.

## Final status

**UNRESOLVED.** V2 artifact identity, script-level sampling/splitting procedure, configured source file, and intended UDPLag file exclusion are evidenced. Exact generation semantics for the four priority inputs, historical V2 row/split membership, and flow/session-level independence are not. No independent V2 metrics are warranted from the current evidence.
